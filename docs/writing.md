# Write Linear updates and documentation

Apply this policy to AI-written issue descriptions, comments, status updates, handoffs, SOPs and technical guides. Use ASD-STE100 principles for about 80% of the writing. This is the team's writing target. Formal conformity requires checking the complete text against the standard and its dictionary. [ASD-STE100 overview](https://www.asd-ste100.org/STE_faq.html)

- Put the result or required action first. Name the actor. Use active voice and direct instructions.
- Use one action or idea per sentence. Keep sentences short. Put multi-step procedures in numbered lists.
- Use one term for each thing. Keep product names, field names, file paths and technical terms exact. Define unfamiliar abbreviations on first use.
- Use specific facts and results. State the owner and next action if work remains. Link the check or the source.
- Use the remaining writing for natural transitions, necessary context, customer wording or an explanation that loses meaning if shortened. Keep exact quotations and legal wording as supplied.

For a Linear update, give the result, the evidence, and the next action or blocker. Include a decision only when the reader needs to make one. Skip fields that add nothing.

**Example**

> The booking check passed on desktop and phone. The test used revision `abc123` in the private preview. The COO will check the live route after release approval.
